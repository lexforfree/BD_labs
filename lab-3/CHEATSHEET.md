## Что показать на демо

1. Открыть `http://localhost:5000`
2. Ввести запрос, например `градиентный спуск` или `вероятность`
3. Переключить методы и показать разницу в результатах и времени:
   - TF-IDF → быстро, точные совпадения слов
   - BM25 → чуть лучше для длинных документов
   - LSA → синонимы (попробовать `обучение` вместо `машинное обучение`)
   - BERT → семантика, первый запуск ждём ~40с, потом быстро
   - DAAT → строгий AND, мало результатов
   - TAAT → мягкий OR, больше результатов
   - **PPR → показать граф**: сущности запроса, seed-узлы, распространение ранга
4. В PPR обратить внимание на D3-граф: seed красные, результаты синие, соседи серые
5. Обратить внимание на PageRank у топовых статей — он выше у статей про базовые понятия

## Вопросы, которые точно зададут

**— Что такое PageRank и как он считается?**  
Числовая мера «авторитетности» страницы, основанная на графе ссылок. Базовая идея: страница важна, если на неё ссылаются важные страницы. Формула:
```
PR(v) = (1-d)/N  +  d * Σ PR(u)/out_degree(u)  для всех u→v
```
`d = 0.85` — damping factor (вероятность продолжить случайное блуждание, а не перейти на случайную страницу). Считается итеративно до сходимости.

**— Чем MapReduce и Pregel отличаются как подходы?**  
MapReduce — батчевая обработка: явные фазы map (разослать вклады) и reduce (собрать, применить damping). Одна итерация = один MapReduce-джоб.  
Pregel — модель сообщений (BSP): каждый узел отправляет сообщения соседям, получает ответы, обновляет состояние. Узлы «голосуют за завершение» когда не меняются. Ближе к реальным графовым фреймворкам (Apache Giraph, Spark GraphX).

**— Почему граф ссылок синтетический, а не реальный?**  
HuggingFace wikipedia dataset содержит plain text без вики-разметки — ссылки `[[статья]]` уже удалены. Wikimedia dumps с ссылками весят сотни ГБ. Для лаб-целей построили граф через TF-IDF cosine similarity: семантически похожие статьи ссылаются друг на друга. Это валидная альтернатива — именно так работают citation-graph системы.

**— Чем TF-IDF отличается от BM25?**  
BM25 — улучшенная версия TF-IDF с двумя исправлениями:  
1. Насыщение TF: при большом числе вхождений прирост score замедляется (через `k1`)  
2. Нормализация длины документа: длинный документ не получает бонус только за длину (через `b`)  
На практике BM25 почти всегда лучше TF-IDF для поиска.

**— Что такое LSA и зачем SVD?**  
LSA (Latent Semantic Analysis) — находит скрытые тематические оси в тексте. TF-IDF матрица разлагается через SVD: `D ≈ U·Σ·Vᵀ`. Берём top-100 компонент — это 100 «тем». Документы и запросы сравниваются в этом пространстве. Ловит синонимию: `авто` и `машина` окажутся рядом, даже если словари разные.

**— Чем BERT лучше TF-IDF?**  
TF-IDF видит только буквальные совпадения слов. BERT — предобученная нейросеть-трансформер, которая понимает смысл предложения с учётом контекста. Запрос `обнаружение закономерностей` найдёт статью про `машинное обучение`, даже если эти слова там не встречаются.

**— В чём разница DAAT и TAAT?**  
DAAT (Document-At-A-Time): итерируемся по документам, проверяем наличие всех термов — возвращает AND. Эффективен при небольшом пересечении постинг-листов.  
TAAT (Term-At-A-Time): итерируемся по термам, аккумулируем score по документам — возвращает OR. Эффективен при коротких запросах и большом числе документов.

**— Что такое PPR и чем отличается от обычного PageRank?**  
Personalized PageRank — версия PageRank, где стартовая вероятность сосредоточена не равномерно, а в конкретных «seed»-узлах, связанных с запросом. Формула:
```
r = (1-d)*p  +  d * A_norm * r
```
где `p` — персонализированный вектор (seeds получают высокий вес, остальные — 0). Ранг распространяется по графу от seed-узлов, поднимая связанные с ними документы.

**— Как строится граф сущностей и почему не используется LLM?**  
spaCy (`ru_core_news_md`) извлекает именованные сущности (NER) и последовательности существительных из каждой статьи. Два документа соединяются ребром если разделяют хотя бы одну сущность; вес ребра = число общих сущностей. LLM не нужен: для извлечения сущностей достаточно лингвистической модели, это дешевле и работает офлайн. HippoRAG делает то же самое, но использует GPT для извлечения полных триплетов (субъект, отношение, объект) — точнее, но дороже.

**— Почему все PageRank значения одинаковы? / Что такое dangling nodes?**  
Dangling node — узел без исходящих рёбер. Если все узлы dangling, то в каждой итерации ранг перераспределяется равномерно и все значения = 1/N. В нашем случае граф построен через TF-IDF similarity — у каждого узла ровно 5 исходящих рёбер, dangling нет, PageRank значим.

## Ключевые формулы

**TF-IDF:**
```
tf(t,d)   = count(t,d) / |d|
idf(t)    = log((N+1)/(df(t)+1)) + 1
score     = cosine(tfidf(q), tfidf(d))
```

**BM25:**
```
score = Σ idf(t) * [tf*(k1+1)] / [tf + k1*(1-b+b*|d|/avgdl)]
k1=1.5, b=0.75
```

**PageRank:**
```
PR(v) = (1-d)/N + d * Σ_{u→v} PR(u)/out(u)
d=0.85, итерации до |ΔPR| < ε
```

**PPR:**
```
r_new(v) = (1-d)*p(v) + d * Σ_{u→v} r(u)*w(u,v) / Σ_w w(u,w)
p — персонализированный вектор (seeds), d=0.85
```

**SVD (LSA):**
```
D[m×n] ≈ U[m×k] · Σ[k×k] · Vᵀ[k×n],  k=100
```

## Архитектура одной фразой

> Статьи скачиваются стримингом из HuggingFace, индексируются в инвертированный индекс, PageRank считается двумя способами (MapReduce и Pregel-BSP) на TF-IDF графе схожести, поиск работает семью методами (TF-IDF, BM25, LSA, BERT, DAAT, TAAT, PPR), PPR использует граф сущностей spaCy и визуализирует результаты через D3.js, Flask UI на порту 5000.

## Что может пойти не так на демо

| Проблема | Причина | Решение |
|---|---|---|
| BERT долго на первый запрос | модель грузится в фоне при старте | подождать ~40с после запуска контейнера |
| DAAT возвращает 0 результатов | запрос содержит редкое слово | попробовать более общий запрос |
| PPR возвращает 0 результатов | spaCy не нашёл сущностей в запросе | попробовать запрос с конкретными терминами: `нейронная сеть`, `теорема Байеса` |
| Граф D3 не отображается | PPR не выбран или 0 результатов | выбрать метод PPR и ввести осмысленный запрос |
| PageRank одинаковый | нет файла `pagerank_mr.pkl` | перезапустить `prepare_data.sh` |
| `articles.jsonl not found` | не запущен `prepare_data.sh` | запустить `./prepare_data.sh` |
